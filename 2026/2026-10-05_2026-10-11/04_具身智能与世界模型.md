# 方向报告 04｜具身智能、机器人与世界模型

**周期：** 2026-10-05—2026-10-11  
**核心判断：** 具身智能的核心不是让机器人“看起来会做”，而是从有限示范中学到能在变化环境执行、纠错和迁移的动作策略。

## 本期判断

机器人学习依赖数据采集、策略模型、仿真环境、物理引擎和真实硬件。VLA 将视觉/语言与动作联系起来，但数据分布、机器人本体和动作空间仍限制泛化。世界模型也要区分“生成未来画面”与“能支持决策的环境动态模型”。术语见[机器人词典](../../glossary/robotics.md)。

## 10 个项目精读

### 1. [LeRobot](https://github.com/huggingface/lerobot) — 标准化机器人数据与策略工具链
**背景：** 机器人数据格式、设备接口和训练流程碎片化。**方法：** 提供数据集、机器人接口、策略训练与评估工具。**解决了什么：** 降低从示范采集到训练基线的工程成本。**影响：** 标准接口有望让研究者把精力放到任务与泛化上。**阅读路线：** 数据格式 → 采集/回放接口 → 策略训练入口 → 评测脚本 → 许可与硬件配置。

### 2. [Open X-Embodiment](https://github.com/google-deepmind/open_x_embodiment) — 跨机器人示范数据
**背景：** 单一机器人数据有限，策略容易过拟合某一机械臂或动作空间。**方法：** 汇集多种机器人和任务数据，并标准化部分动作/观察表示。**解决了什么：** 为跨本体训练提供数据基础。**影响：** 数据覆盖可能改善泛化，但不同本体动作语义和采集质量并不一致。**阅读路线：** schema → 本体与动作空间 → 任务分布 → 基准 → 跨本体泛化证据。

### 3. [OpenPI](https://github.com/Physical-Intelligence/openpi) — 开放 VLA/机器人策略代码
**背景：** 视觉语言模型不直接理解控制频率、动作约束和物理反馈。**方法：** 将视觉/语言条件与机器人动作策略结合，提供训练和运行代码入口。**解决了什么：** 让研究者检查 VLA 如何从观察和指令生成动作。**影响：** 开放代码推动对比实验，实际复现依赖权重、数据、硬件与许可。**阅读路线：** 模型/硬件支持 → observation/action schema → 策略前向与训练配置 → 任务成功率和失败轨迹。

### 4. [Isaac Lab](https://github.com/isaac-sim/IsaacLab) — 并行机器人学习仿真
**背景：** 真实机器人采样慢且昂贵，强化学习需要大量交互。**方法：** 在仿真中组织机器人场景、任务、奖励、传感器和并行环境。**解决了什么：** 加速策略训练和重复评估。**影响：** 大规模仿真提高实验速度，但物理建模、奖励设计和域差异决定迁移效果。**阅读路线：** task config → 场景资产 → 观测/奖励 → 并行 rollout → 随机化和真实迁移条件。

### 5. [MuJoCo](https://github.com/google-deepmind/mujoco) — 接触动力学与控制仿真
**背景：** 抓取、行走和接触操作依赖动力学与接触求解。**方法：** 提供刚体动力学和接触仿真引擎。**解决了什么：** 支持控制算法开发、仿真训练和物理实验。**影响：** 物理引擎是研究底座，但摩擦、材料和执行器仍可能与现实不一致。**阅读路线：** 模型描述 → 关节/接触参数 → 仿真步进与控制频率 → 示例控制器 → 参数误差。

### 6. [robomimic](https://github.com/ARISE-Initiative/robomimic) — 从示范学习操作策略
**背景：** 示范可避免从随机探索开始，但覆盖不足会限制策略。**方法：** 提供模仿学习算法、数据处理和实验配置。**解决了什么：** 在统一任务和数据上比较行为克隆与序列策略。**影响：** 数据质量和失败类型分析与模型结构同样重要。**阅读路线：** 数据格式 → policy 输入输出 → loss/训练配置 → baseline → 分析分布外失败。

### 7. [DROID Policy Learning](https://github.com/droid-dataset/droid_policy_learning) — 基于真实机器人数据的策略学习
**背景：** 真实示范分布广，但采集设置和任务变化使训练数据不一致。**方法：** 提供基于 DROID 数据进行策略学习与评估的代码入口。**解决了什么：** 连接大规模真实示范数据和可复现训练。**影响：** 真实数据可能缩小仿真差距，但本体和任务分布需明确。**阅读路线：** 数据许可/字段 → 预处理 → 训练/评测脚本 → 数据规模与任务切分。

### 8. [HomeRobot](https://github.com/facebookresearch/home-robot) — 家庭场景导航与操作
**背景：** 家庭任务面对开放场景、移动障碍和多阶段动作，不是单一抓取 benchmark。**方法：** 将导航、感知、操作与仿真/机器人接口组织为研究框架。**解决了什么：** 支持家庭场景下的 embodied AI 任务研究。**影响：** 家庭任务暴露系统级失败，但仿真或单一平台结果不能外推到普通家庭。**阅读路线：** 任务执行链 → 导航/操作接口 → 环境和数据 → 成功条件 → 真实硬件依赖。

### 9. [Bullet Physics](https://github.com/bulletphysics/bullet3) — 通用物理仿真
**背景：** 机器人和交互环境需要动力学、碰撞检测和接触求解。**方法：** 提供物理引擎及相关仿真接口。**解决了什么：** 支持机器人、游戏和物理交互场景模拟。**影响：** 引擎选择影响速度和接触行为，需按精度、稳定性和生态权衡。**阅读路线：** 刚体示例 → 碰撞/接触求解 → 约束与时间步 → 控制接口 → 同场景对比另一引擎。

### 10. [UniAD](https://github.com/OpenDriveLab/UniAD) — 自动驾驶统一感知规划的相邻案例
**背景：** 具身系统与自动驾驶都需要把感知转成行动，但环境和动作空间不同。**方法：** 在驾驶任务中统一感知、预测和规划模块。**解决了什么：** 研究任务协同和规划导向学习，并非通用机器人策略。**影响：** 可作为感知到行动的架构对照，不能把驾驶结果当成机器人泛化证据。**阅读路线：** 任务图 → 模块/损失 → 消融 → 区分驾驶域与机器人域的假设。

## 方法论沉淀

机器人结果要报告任务定义、机器人本体、动作空间、数据来源、试验次数、成功率分布和失败恢复能力。仿真训练结果需明确 sim-to-real 证据。项目清单是长期研究地图，不是官方周增 Star 排名。
