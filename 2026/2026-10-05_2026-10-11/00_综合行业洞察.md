# 开源科技与数学研究｜综合行业洞察

**统计周期：** 2026-10-05—2026-10-11　**整理日期：** 2026-10-13

## 结论先行

1. **AI 的边界正在从回答问题推进到产出可检查的工作成果。** Agent 把工具、状态、测试与恢复组合成流程；AI 数学的价值则不只是生成解释，而是提出可供数学家审查、部分可由 Lean 内核检查的研究工件。共同趋势是：输出越接近真实工作，验证链就越重要。
2. **推理成本和执行可靠性正在成为系统架构问题。** LLM 服务端通过 KV Cache 管理、动态批处理、量化和统一网关优化成本与吞吐；Agent 端通过状态图、记忆、权限、测试和 tracing 降低失败成本。
3. **AI 数学是本期最强的科学研究信号。** [OpenAI/math](https://github.com/openai/math) 于 2026 年 10 月公开了由内部模型产生的数学手稿与证明材料。官方 README 当前列出 722 篇手稿、372 个结果家族，横跨多个数学分支；并非所有结果都已有 Lean 形式化，公开记录也包含撤回和修订。这可能影响数学研究的选题、探索和验证工作流，但不能把目录规模直接等同于已被共同体确认的新定理。[官方仓库](https://github.com/openai/math) · [修订历史](https://github.com/openai/math/blob/main/history.md)
4. **自动驾驶与具身智能的难点仍是闭环与迁移。** 离线指标或演示视频不能替代闭环仿真、跨场景测试和真实硬件验证；世界模型/VLA 的实际影响取决于动作可靠性、失败恢复和 sim-to-real 落差。
5. **热度与技术判断必须拆开。** 趋势线索用于发现项目，精读用于理解方法，复现与独立验证用于判断可信度。没有同口径周初/周末快照的方向，不发布虚构 Star 排名。

## 跨领域方法论沉淀

- 把“提出答案”和“验证答案”拆成两条链。LLM 生成、Agent 工具执行、自动驾驶规划和数学证明都需要独立验证器或外部反馈。
- 阅读架构时沿数据流追踪：入口、核心状态/表示、决策模块、执行模块、测试与失败路径，再对照论文和 README 的声明。
- 把系统边界画出来：模型、确定性代码、外部工具和人工审批分别负责什么。
- 基准必须带条件：模型/版本、数据、硬件、输入规模、运行参数和统计方法都要记录。
- 影响判断写成可证伪推断，明确哪些证据会让结论增强或减弱。

## 本期持续观察

1. OpenAI/math 的论文修订、撤回、独立评议和 Lean 形式化覆盖率。
2. Agent 工具能否在固定任务集上降低人工返工，而不只是展示成功 demo。
3. 推理框架在相同模型、硬件、上下文和并发条件下的质量—延迟—成本权衡。
4. 自动驾驶/机器人项目从离线指标进入闭环仿真和真实硬件的证据。
5. 下期开始保存同一项目池的周初/周末 Star 快照，积累可比历史序列。
