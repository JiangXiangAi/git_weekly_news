# AI Agent｜项目精读手册与 Roadmap

## 一、参考架构与原则

可靠的 Agent 至少包括任务入口、上下文构建、工具注册与权限、状态/记忆、执行循环、结果验证、失败恢复、审计与人工审批。建议把模型决策和确定性控制分开：模型提出动作，执行器校验参数和权限，工具返回结构化结果，验证器决定继续、重试、回滚或请人确认。删除文件、部署、付款和外部发送等副作用操作要有明确授权或人工审批。

## 二、10 个项目逐项精读

### 1. [morluto/rea](https://github.com/morluto/rea) — Agent 驱动的软件行为理解
**问题：** 从可观察行为推断软件界面、状态与流程，帮助理解既有软件。
**精读：** 输入证据、探索策略、行为轨迹、生成结果验证，以及 Web 与原生二进制场景差异。
**实战：** 只在自有或获授权应用上定义固定任务集，记录操作轨迹和重建行为差异。
**指标：** 任务成功率、状态覆盖率、行为一致性、人工修复时间。
**风险：** demo 成功不代表复杂软件可完整重建；必须尊重授权和许可。

### 2. [mattpocock/skills](https://github.com/mattpocock/skills) — 可复用技能
**问题：** 把提示词中的操作经验转成可版本化、可组合、可测试的技能。
**精读：** 目录与元数据、触发条件、输入输出、步骤约束、依赖和版本兼容。
**实战：** 写一个代码审查 skill，明确输入、输出 schema、步骤和验收测试；与纯 prompt 对照。
**指标：** 成功率、输出合规率、跨仓库复用成本、回归通过率。
**风险：** 技能可能过时或携带不安全指令；执行前应检查权限。

### 3. [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem) — 跨会话记忆
**问题：** 长任务要决定什么信息值得保存、何时检索、如何更新或遗忘。
**精读：** 事件采集、摘要压缩、索引检索、上下文注入、重复处理、删除机制和隐私。
**实战：** 设计 20 个跨会话任务，比较无记忆、全文历史和摘要检索三种设置。
**指标：** 事实召回率、错误记忆率、token 成本、删除是否生效。
**风险：** 错误记忆会长期污染决策；需要可查看和删除机制。

### 4. [michael-denyer/pstack-claude](https://github.com/michael-denyer/pstack-claude) — 编码工作流适配
**问题：** 将编码任务拆成可复用、可检查的阶段。
**精读：** 阶段定义、上下文交接、状态文件、验证钩子和宿主平台依赖。
**实战：** 对固定 bugfix 比较单轮提示、分阶段流程和带复核流程。
**指标：** 测试通过率、返工次数、人工时间、模型成本。
**风险：** 流程模板不保证正确；平台专用能力会降低可移植性。

### 5. [tester-army/e2e](https://github.com/tester-army/e2e) — Agent 端到端测试
**问题：** 将自然语言测试转成浏览器操作、断言和报告。
**精读：** 页面定位、等待/重试、断言、截图与 trace、测试数据隔离、flaky 测试。
**实战：** 固定 10 个 Web 流程，多次重复运行，记录通过率、误报、漏报和时间。
**指标：** 稳定性、缺陷检出率、失败诊断能力、CI 成本。
**风险：** 关键路径仍应有确定性断言；测试数据要与真实用户隔离。

### 6. [alibaba/open-code-review](https://github.com/alibaba/open-code-review) — 代码审查
**问题：** 结合静态规则与 LLM 找问题，降低无效评论。
**精读：** diff 预处理、规则引擎、模型调用、评论定位、去重、优先级和 CI 集成。
**实战：** 在历史 PR 上盲测纯规则、纯 LLM 和混合方案，由人工标注真实问题。
**指标：** precision/recall、每 PR 误报数、严重问题召回、审查耗时。
**风险：** 安全建议可能错误；源代码和密钥不可无控制地发送给外部服务。

### 7. [earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad) — 自然语言到 CAD
**问题：** 将需求转成可检查的几何结构，而不只是示意图。
**精读：** 中间表示、几何约束、CAD 后端、单位/坐标、导出格式与有效性检查。
**实战：** 从简单支架开始，给出尺寸、公差和孔位，生成后用脚本检查几何。
**指标：** 几何有效率、尺寸误差、约束满足率、人工修复时间。
**风险：** 输出必须经过 CAD 内核和制造约束检查。

### 8. [mvschwarz/openrig](https://github.com/mvschwarz/openrig) — 多 Agent 协作
**问题：** 角色拆分是否提升复杂任务质量，还是只增加协调成本。
**精读：** 角色、共享上下文、任务分配、并发、冲突解决、最终合并和验证。
**实战：** 固定任务，比较单 Agent、顺序多 Agent 和并行多 Agent，多次重复。
**指标：** 成功率、墙钟时间、token 成本、冲突数、人工修复量。
**风险：** 多 Agent 扩大提示注入面；所有角色都需遵守同一权限边界。

### 9. [openai/openai-agents-python](https://github.com/openai/openai-agents-python) — Agent SDK
**问题：** 将工具调用、handoff、trace 和 guardrail 变成可组合的软件结构。
**精读：** Agent/Runner、tool schema、handoff、context、tracing、guardrail 和异常处理。
**实战：** 构建只读检索 Agent，再增加一个必须审批的写操作；注入错误参数和超时。
**指标：** 参数合规率、失败恢复、trace 完整度、越权阻断率。
**风险：** SDK 提供机制不代表应用已经安全；工具执行边界必须再次验权。

### 10. [langchain-ai/langgraph](https://github.com/langchain-ai/langgraph) — 有状态工作流
**问题：** 长任务需要明确状态、循环、分支、checkpoint 和人工介入点。
**精读：** 状态 schema、节点/边、条件路由、持久化、恢复、interrupt、人类审批和测试。
**实战：** 实现“检索→草拟→验证→审批→发布”流程，模拟中断后恢复，检查是否重复执行副作用。
**指标：** 恢复正确率、重复副作用率、故障定位时间、节点成本。
**风险：** checkpoint 可能含敏感数据；恢复逻辑需要幂等与保留策略。

## 三、6 周 Roadmap

| 周次 | 学习重点 | 交付 |
|---|---|---|
| 1 | 工具调用、JSON schema、单 Agent | 只读工具 Agent 与单元测试 |
| 2 | Skills 与任务拆分 | 两个可复用 skill 和回归用例 |
| 3 | Memory 与上下文工程 | 20 个任务的记忆对照实验 |
| 4 | 状态图、checkpoint、重试 | 可中断、可恢复工作流 |
| 5 | E2E、代码审查、guardrails | 固定基准集和 precision/recall 报告 |
| 6 | 多 Agent 与安全评估 | 单/多 Agent 对照、权限与注入测试 |

## 四、毕业项目：可审计的代码维护 Agent
输入 issue，在隔离分支分析代码、提出补丁、运行测试并生成 PR 草稿。默认不自动合并、不接触生产密钥。记录每一步工具调用、输入输出、成本和审批。

**验收：** 固定 20 个任务，报告成功率、测试通过率、误改率、人工介入与成本；所有写操作可审计、可回滚。

## 五、精读顺序
OpenAI Agents SDK → LangGraph → skills → claude-mem → e2e/open-code-review → text-to-cad → openrig/rea。先掌握执行循环与状态，再看专业工具和复杂协作。
