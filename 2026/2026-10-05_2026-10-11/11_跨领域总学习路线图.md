# 跨领域总学习路线图｜LLM、Agent、自动驾驶、具身智能与 AI 数学

## 一、总体策略

不要同时从零学习五个方向。先建立通用工程基础，再选一个主修方向和一个相邻方向。Agent 是连接 LLM 与领域应用的工程层；自动驾驶与具身智能共享感知、时序、规划和仿真思想；AI 数学需要更强的逻辑、形式化和证据意识。

## 二、阶段路线

### 阶段 0：通用基础（2–4 周）
学习 Python、Git、Linux、虚拟环境、单元测试、日志、线性代数、概率统计和优化基础。
**交付：** 有测试、README、环境锁定和可重复运行命令的小项目。

### 阶段 1：LLM 基础与推理服务（4–6 周）
学习 tokenizer、生成参数、模型 API、网关、重试/限流、成本与隐私、本地推理、量化和服务端调度。
**交付：** 统一 benchmark，报告质量、吞吐、延迟、内存与成本。

### 阶段 2：Agent 工程（4–6 周）
学习工具调用、状态机、checkpoint、记忆、验证器、技能封装、自动测试、tracing、权限边界与人工审批。
**交付：** 可审计的 issue-to-PR 草稿 Agent，默认不自动合并。

### 阶段 3A：自动驾驶主线（8 周）
坐标变换和同步 → 多传感器数据 → 3D 感知 → 预测/规划 → CARLA 闭环仿真 → ROS 2/Autoware 或 Apollo 集成。
**交付：** 固定场景集、基线、故障注入和安全限制报告。

### 阶段 3B：具身智能主线（8 周）
机器人坐标和控制 → 仿真器 → 遥操作/示教数据 → 行为克隆 → VLA → 域随机化与 sim-to-real。
**交付：** 仿真桌面操作任务，报告分阶段成功率和跨场景泛化。

### 阶段 3C：AI 数学主线（8 周）
逻辑与证明结构 → Lean/Mathlib → 符号计算 → 神经符号推理 → 数据验证与污染检查 → CI/Blueprint。
**交付：** 含多个 Lean 证明、自动 CI 和依赖图的小型形式化项目。

## 三、按兴趣选择主线

| 兴趣 | 主线 | 相邻方向 |
|---|---|---|
| 模型效率、推理性能 | LLM Serving | Agent |
| 自动化软件开发 | Agent | LLM Serving |
| 感知、规划、车辆系统 | 自动驾驶 | 具身智能 |
| 机器人、动作策略、VLA | 具身智能 | Agent/世界模型 |
| 逻辑、证明、科学计算 | AI 数学 | LLM 推理与验证器 |

## 四、每周节奏
- 40% 阅读源码与论文：带着问题阅读，不只看 README。
- 40% 实验与复现：每次只改一个主要变量。
- 20% 记录结果：环境、commit、配置、结果、失败案例和下一步。
- 每周至少从头复跑一次；无法复跑的结论标为暂定。

## 五、统一项目精读模板
每个仓库必须回答：
1. 项目定位：解决什么问题，目标用户是谁？
2. 背景：旧方案为什么不够？
3. 核心设计：架构、算法、关键模块与数据流。
4. 代码地图：入口、核心目录、配置、测试和训练/推理脚本。
5. 运行路径：最小样例、依赖、硬件、输入输出。
6. 基准证据：指标、对照基线、硬件/数据、失败案例。
7. 许可与风险：代码/模型/数据许可、安全与隐私。
8. 实战任务：最小实验和扩展实验。
9. 验收标准：可量化结果、测试与复现命令。
10. 个人结论：适用与不适用场景、下一步阅读内容。

## 六、今后每期周报标准
1. 本周趋势与结论先行。
2. 每个方向精选 10 个项目。
3. 每个项目包含背景、核心设计、代码地图、关键技术、运行/复现、基准与限制、学习任务。
4. 每个方向附 6–8 周 Roadmap 和毕业项目。
5. 总报告串联跨方向关系、技术依赖与研究机会。
6. 跨期变化只依据已保存的同口径快照。
7. 附来源、采集时间、许可和不确定性。

**质量原则：** 没有实际阅读官方 README/代码/论文，不声称已经精读源码。官方说明、论文结论与我们的推断应分开。Star 是发现线索，不是技术质量的替代指标。
