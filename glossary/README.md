## 报告里的悬停释义

正文第一次出现重要术语时，使用**标准 Markdown 链接 + 链接 title**。桌面浏览器通常会在鼠标悬停时显示 title 浮框；点击后打开词典中更完整的解释。示例：

`[PagedAttention](../../glossary/llm.md#pagedattention "PagedAttention：以分页式块管理 KV Cache，降低连续显存分配约束并支持灵活调度")`

注意：
- title 中写一条独立可读的短释义，而不是只重复英文全称。
- 词条标题应有稳定锚点；正文使用相对路径，确保报告移动到下一期目录后仍能正确指向根目录 glossary。
- Markdown 的悬停提示由浏览器/GitHub 界面决定，不能保证所有移动端或所有客户端都会显示；因此术语仍需链接到完整词条，不能把关键解释只放在浮框里。
- 避免对同一个词每次重复解释；首次链接，后文直接使用，只有语义切换或容易混淆时再补链接。

## 词条编写标准

1. **定义和边界**：给出中英文全称、中文译名、所指对象，并说明不等同于什么。
2. **问题与机制**：说明它要解决的瓶颈，解释数据流、算法步骤、系统组件或关键公式。
3. **关键假设和代价**：写明成立条件、计算/内存/延迟/数据依赖及可能的失败模式。
4. **与邻近概念对照**：解释为何不是一个可随意互换的同义词，最好用小表格比较。
5. **证据和延伸阅读**：优先链接原始论文、官方文档、规范或实现；对仍有争议的说法标注不确定性。

## 跨期维护规则

- 先检索现有词条，避免每周重建同义条目。
- 词典总结的是跨项目可复用的技术知识，不要求每个条目都来自当周 Top 10。
- 把稳定概念放进词典，把易变的版本参数、项目实现细节放进当期报告并链接来源。
- 不把项目方宣传或报告中的推断写成无条件成立的技术事实。
