# Agent 与软件工程词典

- **Agent**：根据目标选择动作、调用工具并根据反馈继续执行的软件系统。是否称为 Agent 不代表其可靠，关键在状态、工具边界和反馈闭环。
- **工具调用**：模型提出结构化工具请求，由宿主程序校验并执行。参数是不可信输入，执行层必须做 schema、权限和资源校验。
- **Handoff**：把任务控制权从一个 Agent/节点交给另一个执行单元。需要定义交接上下文、责任和失败回退。
- **状态图**：以节点和条件边描述任务流程，适合表达分支、循环、恢复和人工审批。
- **Checkpoint**：保存工作流状态以便中断后恢复。恢复时要处理过期状态、重复执行和副作用幂等性。
- **记忆**：为后续任务选择性保留信息。要区分原始对话、摘要、事实库和检索文档；记忆也可能错误、过期或敏感。
- **RAG**：先检索外部资料，再将片段提供给模型生成答案。检索到材料不等于材料可信，回答仍需证据核对。
- **Skill**：把任务说明、资源、脚本和约束打包成可复用模块。技能本身不是沙箱，指令和脚本仍需审查。
- **Tracing**：记录模型调用、工具输入输出、耗时和异常，用于调试和成本分析。日志需脱敏。
- **Guardrail**：对输入、动作、输出或流程施加限制。可靠防护应尽量放在确定性执行层，而非只依赖模型自我承诺。
- **幂等性**：同一操作重复执行不会产生额外副作用，是断点恢复和安全重试的重要前提。
- **Agent 评测**：用固定任务集和明确成功条件评估整个执行链，不只评最终文本，还要评工具误用、重复副作用和人工返工。
